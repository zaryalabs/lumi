# План реализации Lumi 0.3.0: обучение после чтения

Status: `planned`

Целевой релиз: `0.3.0`

Последнее обновление: 2026-07-26

## Владение feature contracts

`0.3.0`:

- **поставляет:** `RD-010`, `LRN-001`, `LRN-003`, `LRN-004`, `LRN-005`,
  `LRN-006`, `CORE-014`, `AI-006`;
- **расширяет:** `RD-011`, `AI-002`, `AI-003`, `AI-005`, `AI-007`, `AI-008`;
- **требует:** `CORE-010`, `CORE-013`, `AI-001`, `AI-002`, `AI-005`,
  `AI-007`, `AI-008`.

`0.3.0` не поставляет `SEARCH-003`/`SEARCH-005`. Learning generation и
explain-back работают только по явно выбранному bounded source scope через
`SourceContextResolver` `0.2.0`.

## Назначение

Этот документ превращает принятый design обучения после чтения в поэтапный
план web-релиза `0.3.0`. Релиз должен закрыть три пользовательских обещания:

1. после завершения главы или материала можно пройти короткий тест, отвечая
   текстом, выбором варианта или голосом;
2. ранее прочитанное возвращается в ограниченную сессию повторения с
   раскрывающимися подсказками и планированием по FSRS, которое можно отключить
   или поставить на паузу;
3. пользователь может объяснить прочитанное своими словами, а ИИ даст
   source-backed обратную связь и предложит уточнить пробелы.

План реализует:

- [продуктовый vision](../vision.md#обучение-после-чтения);
- [механики обучения](../systems/learning.md);
- [интеграцию learning в reader](../systems/reading-screen.md#обучающие-механики);
- [контракты нормализованного контента и anchors](../systems/normalized-content.md);
- [ИИ-слой](../systems/ai.md);
- [очередь ИИ-задач](../systems/ai-task-queue.md);
- [explicit source context для ИИ](../systems/ai.md#retrieval-context);
- [API boundaries](../systems/backend-api.md);
- [sync-ready модель](../systems/sync.md);
- [quality и ADR policy](../systems/quality.md).

План временный. Решения о долговечных schema/API/AI/context contracts до
реализации должны быть перенесены в `docs/adr/` и соответствующие документы
`docs/systems/`.

## Связь с соседними релизами

Предшествующий
[`0.2.0-ai-plan.md`](0.2.0-ai-plan.md) владеет общими AI-возможностями:

- BYOK/OpenRouter и server-side secret storage;
- provider abstraction;
- reusable common Job runtime;
- `AiTask`/`AiRun`/artifact contracts и очередь;
- `AiConversation`, messages и streaming transport;
- bounded explicit material/selection context и `AiContextPack`;
- глобальный chat и MCP.

`0.3.0` не создает второй provider, job engine, conversation lifecycle или
context pack builder. Он расширяет контракты `0.2.0` learning-specific task и
artifact kinds, transcription, open-answer evaluation и mode
`explain_back`. Если обязательная capability из `0.2.0` не выпущена,
соответствующий AI/voice этап `0.3.0` заблокирован; deterministic tests,
hints и scheduling при этом могут поставляться и проверяться независимо.

Последующий
[`0.4.0-notes-and-desk-plan.md`](0.4.0-notes-and-desk-plan.md) владеет serious
BM25 + fastText search, Desk и record-scoped RAG. Learning использует bounded
material/selection context из `0.2.0` и не затягивает global search в
`0.3.0`. В `0.4.0` learning items могут быть добавлены в общий индекс отдельным
расширением, но `0.3.0` от этого не зависит.

## Исходное состояние

К началу работы над `0.3.0` уже реализованы:

- cloud-backed web account, PostgreSQL и account-scoped Axum API;
- `Material -> DocumentRevision -> Normalized Content Package`;
- reflowable reader и PDF fidelity reader;
- stable content units, blocks, source locators и source-backed `Anchor`;
- durable material-level `ReadingProgress`;
- idempotency keys для web mutations;
- durable annotations и переход к anchor;
- общий import job lifecycle с retry/cancel/recovery;
- Dioxus hash routing и Playwright E2E infrastructure.

Нужные для learning пробелы:

- `ReadingProgress` хранит одну позицию материала, но не completion events,
  завершение главы и reading timeline;
- в `lumi-core` нет learning contracts;
- в PostgreSQL нет learning items, sessions, attempts, schedules и settings;
- `JobKind` фактически содержит только `Import`; общей AI/job реализации еще
  нет;
- нет user-scoped AI provider configuration, typed AI artifacts и
  transcription;
- нет server-side explicit source context/context packs;
- web routing не содержит `Челленджи` и learning session;
- нет аудиозаписи ответа, transcript review и streaming explain-back.

Это фактическое состояние repository до реализации запланированного `0.2.0`.
К началу AI-этапов `0.3.0` общие job/provider/context/conversation contracts
должны уже быть поставлены предыдущим релизом. Нельзя начинать с одного
post-reading модального окна или компенсировать незавершенный prerequisite
логикой внутри Dioxus-компонента.

## Результат релиза

### Покрытие пользовательских сценариев

| Сценарий | Результат в `0.3.0` |
| --- | --- |
| Тест после чтения | Необязательное предложение после durable completion event; 3-7 заданий и оценка после завершения |
| Закрытые ответы | `single_choice`, `multiple_choice`, `true_false`; проверка без ИИ |
| Открытые ответы | Текст, rubric/expected concepts, AI evaluation либо честная self-check fallback |
| Голосовой ответ | Запись, durable upload, transcription, обязательная проверка transcript перед grading |
| Вопросы по прошлому | Экран `Челленджи` с ограниченной очередью `Сегодня` |
| Подсказки | Последовательное раскрытие; каждая помощь и открытие source записываются в attempt |
| Учет забывания | FSRS за заменяемым `Scheduler` port, с версией алгоритма в schedule |
| Отключение повторений | Глобально и для материала; pause/snooze без удаления истории и без штрафа |
| Explain-back | Итеративная text/voice сессия с source citations и состояниями `understood`, `partial`, `needs_review`, `not_evaluated` |
| Работа без ИИ | Готовые закрытые тесты, подсказки, self-check и FSRS остаются доступны |

### Целевые поверхности

- Reader: completion offer, ручной запуск, возврат к source и обратно в сессию.
- `Челленджи`: `Закрепить сейчас`, `Повторить`, `Объяснить`, `Черновики`.
- Learning session: вопрос, answer input, hints, feedback, source navigation,
  progress и безопасный выход.
- Explain-back session: scope, text/voice input, transcript review, streaming
  feedback, уточняющие итерации и итог.
- Material card: learning summary, ручной запуск и material-level pause.
- Settings: ссылка на provider settings из `0.2.0`, learning defaults,
  scheduling, generation policy и audio retention.

## Scope

### Входит в `0.3.0`

- cloud-backed Web для всех уже поддерживаемых материалов с пригодным текстовым
  слоем;
- material и content-unit scopes; точный anchor scope для ручного запуска;
- versioned learning items, hints, rubrics и source provenance;
- ручное создание/редактирование item и AI-generated drafts;
- immediate recall, scheduled review, manual practice и explain-back sessions;
- deterministic grading закрытых заданий;
- AI grading открытого ответа и self-check fallback;
- FSRS scheduling и bounded due projection;
- использование direct BYOK provider, server-side secret storage и
  source-visible context policy из `0.2.0`;
- learning-specific durable AI tasks для generation и transcription поверх
  общего job/task runtime `0.2.0`;
- использование explicit source context/context packs `0.2.0`, достаточных для
  learning generation и explain-back;
- browser audio recording, transcript review и configurable retention;
- account/material learning settings;
- capability discovery, observability, migrations, unit/integration/E2E и
  security tests;
- account-scoped MCP adapters для list learning items, создания
  learning-generation task и submit answer через те же application services,
  что Web.

### Не входит в `0.3.0`

- native Desktop/Mobile local replica и offline audio transcription;
- push/email/Telegram/in-app delivery напоминаний и настройки, не влияющие на
  поведение без реализованного delivery channel;
- глобальная пользовательская search surface и полный BM25 + fastText rollout
  из `0.4.0`;
- повторная реализация глобального AI chat UI из `0.2.0`;
- отдельный learning MCP worker и external-agent explain-back UI; обычные
  account-scoped user-operation adapters входят в релиз;
- `lum:quiz`/`lum:flashcard` compilation (`LRN-002`) и plugin runtime;
- Anki/Markdown learning import/export;
- полноценный Desk learning view;
- social sharing learning results;
- streaks, leagues, punitive overdue counters и обязательные тесты;
- автоматическая оценка речи, грамотности или способностей пользователя.

### Ограничения форматов

- Reflowable материалы используют `ContentUnit`, normalized blocks и anchors.
- PDF использует page/text-layer anchors. PDF без текстового слоя не передается
  в generation/explain-back; UI объясняет причину и не создает недостоверный
  feedback.
- Повторный импорт создает новую revision. Item остается привязанным к исходной
  revision до успешного anchor recovery или ручного подтверждения.

## Принципы реализации

1. Completion фиксируется раньше learning offer и не откатывается из-за
   dismiss, ошибок ИИ или незавершенной сессии.
2. Learning writes выполняются через application services и versioned Axum API,
   а не через UI-specific server functions.
3. Attempt является append-only evidence. Исправление transcript до grading
   сохраняет provenance, но не переписывает уже завершенную попытку.
4. Schedule является пользовательским состоянием, а mastery — перестраиваемой
   projection.
5. Generated data проходит `task -> artifact -> validation -> draft`; оно не
   становится active молча без отдельной user policy.
6. Source text в AI context считается недоверенными данными, а не
   инструкциями модели.
7. Готовые items и scheduling полезны без provider. AI-unavailable не
   превращается в неправильный ответ.
8. Pause/disable не удаляет items, attempts и history и не создает backlog
   наказаний при resume.
9. Любая сессия имеет видимый размер, сохраняет прогресс и может быть
   остановлена без оценки unanswered items.
10. Reader, Challenges и material card работают с одними primary learning
    objects, а не с копиями.

## Целевая архитектура

```text
Reader completion / manual action / Challenges
  -> Learning application service
     -> PostgreSQL learning repositories
     -> Scheduler port -> FSRS adapter
     -> Source context port -> SourceContextResolver
     -> AI task port -> common Job engine -> provider worker
     -> Interactive AI port -> provider streaming
     -> Blob/attachment port -> voice answer -> transcription task
  -> Axum /api/v1/learning/*
  -> Dioxus learning surfaces
```

Границы модулей:

- `lumi-core::learning`: platform-independent entities, commands, validation,
  deterministic grading и `Scheduler` contract;
- `lumi-core::ai`: расширение shared task/artifact/conversation/provider
  contracts и использование bounded source context/citations из `0.2.0`;
- `lumi-server::learning`: application services, PostgreSQL repositories,
  projections и route handlers;
- `lumi-server::scheduler`: FSRS adapter;
- `lumi-server::ai`: learning task/artifact validators и explain-back mode
  поверх credentials, worker и provider transport `0.2.0`;
- `lumi-server::ai::context`: learning scope policy поверх explicit source
  refs/context packs `0.2.0`;
- `apps/web::learning`: Challenges, session runner, explain-back и settings;
- `apps/web::voice`: browser recording adapter без domain logic.

`imports.rs` и текущий большой `lib.rs` не должны становиться местом learning
business logic. Новые route groups собираются в отдельных модулях и
подключаются в root router.

## Доменные контракты

### Source и completion

`LearningSource` задает immutable source identity:

```text
LearningSource {
  id
  space_id
  material_id
  document_revision_id
  scope_kind: material | content_unit | anchor
  scope_key
  content_unit_id?
  anchor?
  source_hash
  title
  created_at
}
```

Один `scope_key` детерминированно строится из revision и выбранного scope. Он
используется для deduplication, но не заменяет полный source ref.

`ReadingCompletion`:

```text
ReadingCompletion {
  id
  space_id
  user_id
  source_id
  completion_generation
  trigger: reader_boundary | explicit_user_action
  completed_at
}
```

Требования:

- unique constraint на `(user_id, source_id, completion_generation)`;
- retry одной команды возвращает существующий completion;
- reopen уже завершенного scope не увеличивает generation;
- новый generation появляется только после новой revision или явного
  `Пройти заново`;
- исторический progress не backfill-ит intrusive offers. Старые материалы
  доступны для ручного запуска.

### Items и revisions

```text
LearningItem
  -> LearningItemRevision
     -> LearningHint[]
     -> LearningRubric?
```

`LearningItem` хранит identity, source, kind, status, origin и current revision.
Editable payload живет в `LearningItemRevision`, чтобы старые attempts всегда
ссылались на фактически показанную формулировку.

Обязательные варианты `kind`:

- `quiz_single_choice`;
- `quiz_multiple_choice`;
- `quiz_true_false`;
- `open_question`;
- `flashcard`;
- `cloze`;
- `hinted_question`;
- `explain_back_prompt`;
- `reflection_prompt`.

В первой user-visible сессии reflection не оценивается. Flashcard/cloze
участвуют прежде всего в scheduled review. Domain contract сразу принимает все
виды из `LRN-001`, чтобы не делать несовместимую вторую schema migration.

Статусы:

- `draft`;
- `active`;
- `archived`;
- `rejected`.

Origins:

- `user`;
- `author`;
- `ai_generated`;
- `converted_annotation`.

`answer_spec`, `rubric` и hints должны быть typed enums/structs в Rust. JSONB
используется как serialization boundary, но не как замена domain validation.

### Sessions и attempts

```text
LearningSession
  -> LearningSessionItem[]
  -> LearningAttempt[]
     -> LearningAttemptEvent[]
```

Session kinds:

- `immediate_recall`;
- `scheduled_review`;
- `explain_back`;
- `manual_practice`.

Session states:

- `offered`;
- `in_progress`;
- `completed`;
- `dismissed`;
- `abandoned`.

Session item snapshot фиксирует item revision, порядок и reason selection.
Изменение/архивация item не меняет уже начатую сессию.

Attempt хранит:

- item и item revision;
- answer payload;
- deterministic result или evaluation state;
- hints used;
- source opened;
- elapsed time;
- self-check/review rating;
- feedback и citations;
- provider/model/prompt/schema provenance для AI evaluation;
- client/device и timestamps.

Attempt events фиксируют `hint_revealed`, `source_opened`,
`transcript_accepted`, `answer_submitted`, `feedback_received` и
`session_left`. Они позволяют не перегружать mutable attempt record и дают
evidence для scheduler.

### Scheduling и settings

`LearningSchedule` имеет unique `(user_id, item_id)` и хранит:

- state: `new | learning | review | relearning | paused`;
- `due_at`;
- FSRS state fields;
- `last_review_at`, repetitions и lapses;
- algorithm name/version;
- serialized algorithm payload для совместимого upgrade;
- material/source pause marker;
- object revision и timestamps.

`LearningSettings` account-wide:

- scheduling enabled;
- daily limit;
- manual-only mode;
- generation policy;
- generated draft auto-activation policy;
- voice enabled;
- original audio retention policy;
- preferred provider/model refs.

`LearningSourceSettings` переопределяет:

- completion offers;
- scheduling;
- paused state;
- auto-generation.

Folder override не реализуется, пока в библиотеке нет durable folder model.
Schema должна допускать новый scope kind без миграции attempts.

FSRS получает явный review rating. Deterministic correctness, hints и source
open помогают предложить rating, но не маскируются под точное измерение:

- incorrect/blank предлагает `again`;
- correct с существенной помощью не предлагает `easy`;
- показ полного ответа или source до ответа считается assisted recall;
- self-check сохраняется отдельно;
- unanswered item не отправляется scheduler.

Точный mapping и FSRS parameters фиксируются ADR и regression vectors до
реализации adapter.

### AI и voice

Нужные общие сущности:

- `AiProviderCredentialRef`;
- `AiTask`;
- `AiRun`;
- `AiContextPack`;
- `AiArtifact`;
- `AiConversation`;
- `AiMessage`;
- `AudioAttachment`;
- `LearningAttachmentRef`;
- `TranscriptArtifact`.

`AudioAttachment` принадлежит общему personal blob/attachment layer.
Learning хранит stable reference и не вводит собственный uploader/storage
lifecycle. Original audio и versioned `TranscriptArtifact` — разные payloads.
Удаление original audio не удаляет accepted transcript и attempt. Пока
transcription не завершена, attempt находится в `pending_transcription` и не
влияет на schedule.

## API-контракт

Точные request/response schemas утверждаются ADR, но route shape для
`0.3.0` должен быть согласован до UI-реализации.

### Reading completion и offers

```text
POST /api/v1/materials/{material_id}/reading-completions
GET  /api/v1/materials/{material_id}/learning-offer?source_id=...
PATCH /api/v1/materials/{material_id}/learning-settings
```

Completion command содержит revision, scope и idempotency key. Response
возвращает completion и доступные независимые actions, а не автоматически
созданную обязательную session.

### Items и drafts

```text
GET   /api/v1/learning/items
POST  /api/v1/learning/items
GET   /api/v1/learning/items/{item_id}
PATCH /api/v1/learning/items/{item_id}
POST  /api/v1/learning/items/{item_id}/activate
POST  /api/v1/learning/items/{item_id}/archive
POST  /api/v1/learning/generation-tasks
```

List endpoints используют cursor pagination и filters по material, source,
kind и status.

### Sessions и attempts

```text
POST /api/v1/learning/sessions
GET  /api/v1/learning/sessions/{session_id}
POST /api/v1/learning/sessions/{session_id}/start
POST /api/v1/learning/sessions/{session_id}/items/{item_id}/hints/{position}/reveal
POST /api/v1/learning/sessions/{session_id}/items/{item_id}/source-opened
POST /api/v1/learning/sessions/{session_id}/items/{item_id}/attempts
POST /api/v1/learning/sessions/{session_id}/complete
POST /api/v1/learning/sessions/{session_id}/abandon
```

Attempt submission idempotent. Закрытый ответ оценивается в одной транзакции с
persist attempt и optional schedule update. AI evaluation создает pending
attempt/run и завершает его отдельной idempotent command.

### Challenges и scheduling

```text
GET   /api/v1/learning/challenges/today
GET   /api/v1/learning/schedules
PATCH /api/v1/learning/settings
POST  /api/v1/learning/sources/{source_id}/pause
POST  /api/v1/learning/sources/{source_id}/resume
POST  /api/v1/learning/sessions/{session_id}/snooze
```

`today` возвращает bounded sections и counts отдельно. Paused items не входят
в overdue count.

### Explain-back и voice

```text
POST /api/v1/learning/explain-back
GET  /api/v1/learning/explain-back/{session_id}
POST /api/v1/learning/explain-back/{session_id}/messages
POST /api/v1/learning/explain-back/{session_id}/finish

POST /api/v1/blobs/uploads
PUT  /api/v1/blobs/uploads/{upload_id}
POST /api/v1/blobs/uploads/{upload_id}/complete

POST /api/v1/learning/attachments
POST /api/v1/learning/attachments/{attachment_id}/transcribe
DELETE /api/v1/learning/attachments/{attachment_id}/audio
```

`/api/v1/blobs/uploads` — общий upload/complete contract. Learning attachment
command принимает immutable blob ref и связывает его с attempt/session.
Download authorization, MIME/size limits, checksum, retention и orphan cleanup
принадлежат общему `AudioAttachment` layer.

Interactive response использует streaming transport с cancellation и
reconnect-safe persisted turns. Решение SSE или fetch streaming подтверждается
spike; system contract не должен зависеть от browser-only callback.

Все mutations требуют auth, CSRF, ownership checks, idempotency и explicit body
limits. Ошибки используют общий problem response.

## Web UX

### Routing

Расширить `AppRoute`:

```text
#challenges
#learn/session/{session_id}
#learn/explain/{session_id}
#material/{material_id}/learning
#settings/learning
```

Route parsing и browser history покрываются unit/E2E. Активная session
восстанавливается после reload.

### Completion offer

Reader:

1. сохраняет progress/completion;
2. после server ack показывает non-blocking bottom sheet;
3. предлагает `Проверить себя`, `Объяснить своими словами`,
   `Напомнить позже`, `Не сейчас`, `Не предлагать для этого материала`;
4. не показывает offer повторно для того же completion generation;
5. при отсутствии active items предлагает `Создать тест` или explain-back;
6. закрывается без изменения reading progress.

Material и chapter completion определяются semantic content-unit boundary, а
не только `progress_fraction == 1.0`. Для browser-measured pagination adapter
сообщает domain command о достигнутом последнем block выбранного unit.

### Session runner

Обязательные состояния:

- loading/error/retry;
- answer input;
- hint levels;
- transcription pending/edit;
- evaluation pending;
- feedback with citations;
- stopped/resumable;
- completed summary.

UI не показывает правильный ответ до первой попытки или explicit action.
Переход к source сохраняет `return_to` с session/item и возвращает пользователя
к тому же question. Unanswered items не помечаются ошибками.

### Challenges

Первый экран:

- `Сегодня` с оценкой времени и daily limit;
- `Закрепить сейчас`;
- `Повторить`;
- `Объяснить`;
- `Черновики`;
- фильтр по material;
- snooze, pause и manual launch.

Нужно различать `нет заданий`, `повторения выключены`, `все выполнено`,
`provider не настроен` и `generation идет`. Один generic empty state
недостаточен.

### Explain-back

Перед началом показываются scope, ожидаемая длительность и объяснение оценки.
После каждой итерации:

- `Что уже верно`;
- `Что стоит дополнить`;
- `Что искажено`;
- source citations;
- один следующий вопрос.

Доступны `Открыть источник`, `Не согласен`, `Повторить оценку`, `Завершить`.
При недостаточном context результат `not_evaluated`; UI не подменяет его
нулевой оценкой.

### Voice

- Начало записи требует явного click и browser permission.
- UI постоянно показывает recording state, duration и stop/cancel.
- До upload пользователь может прослушать или удалить запись.
- После transcription transcript редактируется и подтверждается.
- Неоднозначный закрытый ответ требует подтверждения выбранного варианта.
- Потеря permission/provider/network оставляет доступным text input.

Все controls имеют labels/roles, status updates используют подходящий live
region, а flow полностью проходим с клавиатуры.

## План поставки: продуктовые эпики

Источник исполнительного порядка — [`ROADMAP.md`](ROADMAP.md). План

### Эпик E1. Обучение после чтения — выполнен

Включает G0, C0, G1, A1, A2 и C1.

Outcome: completion фиксируется до необязательного offer; пользователь проходит
готовую deterministic closed/open self-check session, сохраняет durable

без AI provider.

### Эпик E2. Повторение и Challenges — выполнен

Включает A3 и C2.

Outcome: hints и source assistance входят в evidence, FSRS обновляет

### Эпик E3. AI-обучение и explain-back

Включает B1, B2 и C3.

### Эпик E4. Голосовой контур

Включает B3 и C4.

Outcome: пользователь записывает или загружает ответ, получает durable
transcription, проверяет transcript до grading/explain-back и управляет
retention/delete; text input всегда остаётся fallback.

### Эпик E5. Learning platform и выпуск

Включает A4, сквозную интеграцию V1–V4 и общий Release Gate.

Web; security, accessibility, performance, runbook и operator acceptance
закрывают release `0.3.0`.

Внутри эпика backend, Web, tests и documentation workstreams могут
выполняться независимо после фиксации общего contract. Каждый внутренний пункт

  sync payload.
- Context preview показывает пользователю material/scope и включенные personal
  objects до AI action.
- Source chunks передаются как data envelope; system prompt запрещает следовать
  embedded instructions.
- Generated prompt/options/explanations рендерятся как escaped text или
  sanitized Markdown.
- Audio upload проверяет ownership, MIME sniffing, size/duration и checksum.
- Signed/direct blob access не должен переживать deletion/retention cleanup.
- Attempts, audio, transcripts и explain-back messages не попадают в
  telemetry payload.
- Logs содержат ids, lifecycle, latency, sizes и error codes, но не source,
  answer, transcript, key или raw provider response.
- Account deletion/export policy должна перечислять learning objects и
  attachments до release.

## Observability

Минимальные signals:

- completion created/deduplicated;
- offer shown/dismissed/action selected;
- session created/started/completed/abandoned;
- deterministic attempt result category;
- schedule due/update/pause/resume;
- AI task/run lifecycle, latency, retry и schema validation failure;
- explain-back turn latency/cancel/not-evaluated;
- transcription lifecycle и audio cleanup;
- due projection latency и selected item count.

Нельзя использовать correctness или explain-back outcome как product analytics
без отдельного privacy review. Для operational metrics достаточно технических
counts и durations.

## Rollout и совместимость

1. Миграции создают пустое learning state; существующий `ReadingProgress` не
   создает completion offer задним числом.
2. `learning-core` можно включить раньше UI для repository/API tests.
3. `learning-scheduling` включается после FSRS regression gate.
4. `learning-ai` показывается только при совместимых `0.2.0`
   provider/task/explicit-context capabilities; deterministic functions не
   зависят от флага.
5. `learning-voice` включается только при browser recording и transcription
   capability.
6. Rollback приложения не должен удалять новые tables. Forward-only migrations
   и capability negotiation защищают старый client.
7. Generated drafts и pending attempts сохраняются при временном отключении AI.
8. Algorithm upgrade не переписывает attempts; schedule пересчитывается
   versioned migration/job с audit metadata.

## Риски и меры

| Риск | Мера |
| --- | --- |
| `0.2.0` не поставил нужный AI prerequisite | Не дублировать foundation: не начинать B1 и связанные Web-этапы; исправление делать в owning plan |
| Scope `0.3.0` разрастается до global search | Использовать bounded explicit context `0.2.0`; serious BM25 + fastText и search UI оставить `0.4.0` |
| Недостоверные AI вопросы | Draft-first, schema/source validation, citations, duplicate checks, explicit activation |
| Explain-back выдает уверенный неверный verdict | Structured rubric, citations, `not_evaluated`, dispute/re-evaluate, fake/adversarial provider tests |
| Completion offer раздражает | Durable generation, один offer, material opt-out, ручной запуск сохраняется |
| Pause превращается в backlog | Исключить paused items из overdue и bounded recomputation on resume |
| FSRS привязан к библиотеке/версии | `Scheduler` port, stored algorithm version/payload, regression vectors |
| Голос создает privacy/data-retention проблему | Separate consent/settings, bounded storage, transcript provenance, explicit audio deletion |
| Browser streaming/recording нестабилен | Capability detection, text fallback, transport spike, persisted turns/tasks |
| Concurrent submit портит schedule | Idempotency, unique attempt command key, row lock/optimistic revision, atomic transaction |
| Reimport ломает citations | Revision-bound refs, anchor recovery gate, unresolved state вместо silent remap |
| AI latency блокирует чтение | Generation/transcription background; completion first; explain-back optional |

## Критерии завершения `0.3.0`

Релиз считается завершенным, когда одновременно выполнено следующее:

- пользователь завершает chapter/material и получает ровно одно необязательное
  предложение, не влияющее на reading progress;
- ready closed test полностью работает без ИИ;
- open answer поддерживает text, voice transcript review, AI grading и
  self-check fallback;
- hints/source opening отражаются в attempt и scheduling evidence;
- FSRS scheduling работает, versioned и заменяем;
- global/material disable, pause, resume, snooze и manual-only не теряют data;
- Challenges показывает bounded `Сегодня`, immediate, due, explain и drafts;
- generated items проходят task/artifact/validation/draft flow;
- explain-back дает iterative cited feedback и корректный `not_evaluated`;
- source jump возвращает пользователя в сохраненную session;
- все writes durable, idempotent и account-scoped;
- no-provider и provider-failure paths проверены;
- AI paths используют общие `0.2.0` provider, job, conversation и
  explicit-context contracts без дублирующей реализации;
- learning MCP tools используют те же application commands, permissions и
  idempotency, что Web;
- voice paths используют один generic `AudioAttachment`/blob lifecycle, который
  могут расширять последующие функции;
- audio retention/delete semantics проверены;
- `make c` и `make web-e2e` проходят;
- runbook, capabilities, README и canonical docs обновлены;
- долгоживущие решения из этого плана перенесены в `docs/adr/` и
  `docs/systems/`.
