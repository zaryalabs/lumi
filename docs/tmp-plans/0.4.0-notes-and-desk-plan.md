# План реализации Lumi 0.4.0: записи по чтению, Desk, поиск и RAG

Status: `planned`

Целевой релиз: `0.4.0`

Последнее обновление: 2026-07-25

## Назначение

План переводит уже принятый продуктовый дизайн записей по чтению, Desk и
единого поиска в последовательность реализуемых вертикальных срезов для
релиза `0.4.0`.

Итог релиза:

- пользователь выделяет текст желтым или жирным, меняет стиль и удаляет
  выделение без потери source-backed anchor;
- пользователь создает Markdown-заметку к выделению или самостоятельную
  запись на полях к блоку, разделу, странице или материалу;
- пользователь записывает, воспроизводит и удаляет голосовую заметку,
  привязанную к source anchor;
- пользователь пишет `[[wikilinks]]` в заметках, разрешает неоднозначные
  ссылки и видит обратные ссылки;
- Desk собирает записи всех поддерживаемых типов и группирует их вокруг
  материалов и структуры источника;
- единый поиск находит материалы и записи через BM25 с fastText rerank и
  открывает результат на точном anchor;
- пользователь может задать вопрос по своим записям и получить
  source-backed ответ с цитатами через ограниченный RAG-сценарий.

План не заменяет канонические документы. Решения о schema, sync, blob protocol,
search retrieval и AI contracts до реализации должны быть перенесены в ADR и
соответствующие документы `docs/systems/`.

## Фактическое состояние на момент составления

В репозитории уже есть сильная основа, которую нельзя обходить новым
параллельным контуром:

| Область | Уже реализовано | Разрыв до 0.4.0 |
| --- | --- | --- |
| Anchors | source-backed multi-block `Anchor`, Unicode scalar offsets, recovery ladder, unresolved state | нужна явная гранулярность цели для range/block/section/document/page area |
| Записи | durable `Annotation`, `Highlight` и `Note`, PostgreSQL, optimistic revision, idempotency, tombstones | текущий `AnnotationKind` не выражает margin/voice note, metadata, links и связь note с highlight |
| Хайлайты | yellow/green/blue, reader overlay, reload и repagination coverage | нет жирного стиля, category и полноценного изменения стиля в UI |
| Заметки | Markdown body к выделенному диапазону, редактирование в reader panel | нет самостоятельной записи на полях, title/tags/status, wikilinks и backlinks |
| Voice | content-addressed blobs и общая job-инфраструктура | нет browser recording, audio metadata, voice-note API и UI |
| Desk | канонический design и route/query contract | нет projection, API, top-level route и web surface |
| Search | normalized text layers и канонический BM25 + fastText design | нет index storage, indexing jobs, query/retrieval API и UI |
| RAG | канонические boundaries приняты; BYOK, глобальный чат и базовый context pack запланированы в `0.2.0` | нет serious search и отдельного record scope, пригодного для вопросов по записям |
| Web navigation | hash-based `AppRoute` для Library/Connections/Settings/Reader | нет восстанавливаемых Desk/Search/item routes |
| Export | portable JSON export текущих annotations | schema не покрывает новые типы, audio manifest, links, tags и transcripts |

## Ожидаемый baseline на входе в `0.4.0`

Перед production-работой соответствующих треков должны быть подтверждены:

- `0.2.0`: common `Job` runtime, provider/chat/artifact contracts,
  typed accepted artifacts, `SourceContextResolver` и compatible citations;
- `0.3.0`: generic `AudioAttachment`, blob upload/complete/download,
  browser recorder, retention/GC primitives, learning items, attempts,
  mastery и scheduling.

Таблица выше описывает repository state на дату составления, а не разрешает
повторно реализовать отсутствующий prerequisite внутри `0.4.0`.

Ключевой принцип миграции: существующие annotations остаются валидными,
доступными и экспортируемыми. Новый релиз расширяет текущий durable path, а не
создает рядом вторую модель записей.

## Scope 0.4.0

### Входит

1. Annotation model v2 с обратной совместимостью.
2. Yellow и bold highlights; существующие green/blue сохраняются.
3. Text note к selection и самостоятельная margin note.
4. Tags, простой status и Markdown body для текстовых записей.

7. Внутренние wikilinks, stable `LinkTarget`, unresolved links, autocomplete и
   backlinks для записей и материалов.
8. Material-centered Desk: overview, cross-material records, material records,
   filters, inline edit и переход к source.
9. Learning view в Desk: items, attempts, due/missed/skipped/completed state,
   mastery summary и переход в Challenges/Reader без второго learning store.
10. Сохранённые typed AI artifacts в Desk с provenance и source navigation;
    raw chat и rejected drafts не попадают в Desk.
11. Unified search по доступным в релизе источникам: material metadata,
    normalized content, highlights, notes, margin notes, voice transcripts,
    accepted AI artifacts и learning items.
12. Library/global search, Reader in-document search и поиск/фильтрация в Desk
    поверх общего query contract.
13. BM25 candidate generation, fastText rerank, source-aware chunks, snippets,
    citations и retrieval API.
14. RAG «вопрос по записям» через глобальный чат из `0.2.0`: retrieval только
    по явно выбранному personal record scope, streaming answer и citations.
15. Portable annotation export v2 с readable Markdown/JSON представлением и
    audio manifest.
16. Миграции, rebuild tools, observability, security, accessibility,
    compatibility и performance coverage.
17. MCP adapters для Desk и search поверх тех же query/application services и
    permission rules, что Web.

### Не входит

- автоматическая транскрибация voice notes (`AI-006`);
- повторная реализация глобального ИИ-чата, BYOK/provider и AI task runtime,
  которые принадлежат `0.2.0`;
- новый MCP worker/runtime или фоновая очередь всех AI actions; Desk/search
  user-operation adapters расширяют foundation `0.2.0`;
- полноценная Knowledge Base, graph UI и редактор KB notes;
- Community Space search и shared highlights/comments;
- desktop/mobile local replica и offline local search;
- синхронизация с Obsidian, filesystem watch или companion plugin;
- dense embeddings, ANN/vector database и cross-encoder rerank;
- совместное редактирование и CRDT.

Внутренние `[[wikilinks]]` входят в релиз и не считаются интеграцией с
Obsidian. Файловая интеграция остается `deferred` согласно
[`../systems/obsidian.md`](../systems/obsidian.md).

## Релизные решения

### Одна доменная модель записей

Reader и Desk работают с одним aggregate `Annotation`. Desk хранит только
перестраиваемую read projection и не копирует note body или audio ownership.

Целевая логическая форма:

```text
Annotation {
  id
  material_id
  revision_id
  target: AnnotationTarget
  payload: Highlight | Note | MarginNote | VoiceNote
  related_annotation_id?
  tags[]
  status
  revision
  created_at
  updated_at
}

AnnotationTarget {
  kind: text_range | block | section | document | page_area
  anchor
}
```

Правила:

- highlight всегда имеет `text_range` или PDF `page_area`;
- note к выделению хранится отдельной записью и может ссылаться на highlight
  через `related_annotation_id`;
- margin note не требует selection и использует block/section/document или
  page-area anchor;
- voice note использует тот же target contract;
- `related_annotation_id` не меняет ownership и допускает только доступную
  запись того же personal scope;
- изменение active `DocumentRevision` запускает существующий anchor resolver;
- unresolved запись не удаляется и остается видимой в Desk.

### Highlight style не должен незаметно ломать пагинацию

Yellow является paint-only overlay. Bold визуально меняет начертание и может
изменить метрики текста. До реализации обязателен browser spike:

1. проверить paint-only bold overlay без изменения layout;
2. проверить selection, copy, screen reader и темы;
3. если paint-only вариант недостаточно качественный, принять controlled
   repagination и включить annotation-decoration revision в `PageMap` cache key;
4. закрепить решение ADR/reader fixture.

Нельзя просто обернуть source text в `font-weight: bold`, сохранив старый
`PageMap`.

### Voice note — blob плюс annotation metadata

Audio bytes хранятся в существующем content-addressed blob store. Annotation
хранит ссылку и metadata, но не base64 payload.

```text
VoiceNotePayload {
  audio_attachment_id
  transcript_artifact_id?
  waveform_summary?
}
```

В Web:

- предпочитается `MediaRecorder` с runtime MIME negotiation;
- если запись недоступна, UI предлагает выбрать аудиофайл;
- playback использует доступный browser media element;
- максимальные duration, byte size и MIME allowlist задаются общей server
  audio capability, а не только client validation;
- незавершенный upload не создает voice annotation;
- unreferenced uploaded blob попадает под отдельный grace-period GC;
- удаление voice note создает tombstone, а `AudioAttachment`/blob удаляется
  только после retention/refcount проверки;
- `TranscriptArtifact` не встраивается в annotation payload и сохраняет
  собственную revision/provenance.

### Wikilink — читаемый ввод, stable target

В note body сохраняется исходный Markdown. Parser извлекает wikilinks, а
resolver сохраняет binding:

```text
AnnotationLink {
  id
  source_annotation_id
  raw_text
  display_path
  target_type?
  target_id?
  material_id?
  anchor?
  state: resolved | ambiguous | unresolved
}
```

В 0.4.0 resolver поддерживает:

- material;
- annotation/highlight/margin/voice note;
- anchor/structural path внутри material;
- future target type как безопасный unresolved value.

Переименование изменяет display projection, но не `target_id`. Backlinks
являются rebuildable projection над resolved links. Автоматическое создание KB
note по неизвестному `[[имени]]` не входит в релиз.

### Desk — projection, не aggregate

Desk читает:

```text
Annotation + Material + Anchor resolution + Link/backlink state
  -> DeskMaterialProjection
  -> DeskItemProjection
```

Projection обновляется из durable change/outbox events и полностью
перестраивается командой. Primary запись нельзя потерять из-за сбоя projector.

### Search — производный индекс

Search source of truth:

- PostgreSQL domain state;
- immutable normalized packages/text layers;
- доступные voice transcripts.

Tantivy BM25 index, fastText vectors и snippets являются derived data.
Изменение primary object и постановка index job должны фиксироваться в одной
транзакции через outbox/change record. Сбой индексации не откатывает заметку и
не делает ее невидимой в Desk.

### RAG не принадлежит search engine

Search реализует только:

```text
retrieve(query, scope, filters, top_k, context_policy)
  -> RetrievedChunk[]
```

Существующая AI orchestration из `0.2.0`:

1. проверяет direct provider и personal scope;
2. вызывает `retrieve`;
3. строит bounded context pack;
4. показывает пользователю включенные источники;
5. вызывает provider;
6. стримит ответ с citations;
7. сохраняет ответ в обычной chat history, но не как Desk item автоматически.

Search не вызывает LLM. Record RAG переиспользует полный chat lifecycle
`0.2.0`, а не вводит отдельный answer/session aggregate.

## Persistence и миграция

### Annotation v2

Предпочтительный миграционный путь:

1. Сохранить таблицу `annotations`, ids, ownership, anchor, optimistic revision,
   timestamps и tombstones.
2. Добавить queryable `annotation_type`, `target_kind`, `status`,
   `related_annotation_id` и payload schema marker.
3. Сохранить JSON payload для variant-specific данных; не сериализовать audio
   bytes.
4. Добавить `annotation_tags` и `annotation_links` отдельными таблицами.
5. Хранить voice-note binding с FK на общий `audio_attachments`; media
   metadata и blob lifecycle не дублировать в annotation tables.
6. Backfill:
   - `highlight` из текущего `kind.type = highlight`;
   - `note` из текущего `kind.type = note`;
   - `target_kind = text_range` для range anchor, иначе `block`;
   - `status = active`;
   - текущие colors без изменения.
7. Держать compatibility decoder для `lumi.annotations.v1` и sync schema
   `s1.2026-07-13.anchors-v2`.
8. Повысить domain/sync/export schema marker только вместе с fixtures и
   migration tests.

Точные SQL constraints:

- annotation type и target kind из allowlist;
- positive object revision;
- owner/material/revision scope сохраняется;
- related annotation не может ссылаться на tombstoned/foreign object при
  создании;
- audio attachment ref разрешён только для `voice_note`;
- active `AudioAttachment` ref должен существовать и принадлежать тому же
  `user_id`;
- links и tags каскадно tombstone/rebuild, но не удаляют primary annotation.

### Desk projection

Минимум:

- `desk_material_projection` для counters, last activity и attention states;
- `desk_item_projection` для cursor ordering, material/structural grouping,
  preview и filter fields;
- projector cursor/version;
- rebuild command;
- deterministic projection fixtures.

В projection не хранится authoritative note body. Preview можно
регенерировать из primary object.

### Search metadata

PostgreSQL хранит:

- `search_documents`;
- `search_chunks` metadata/text hash/citation/anchor;
- domain-specific `IndexRequest`/index status, исполняемый общим `Job` с kind
  `search_index`;
- indexed source revision/hash;
- index/chunker/model versions;
- при выбранной реализации — derived fastText vector bytes.

Tantivy index хранится в отдельном configurable directory
`LUMI_SEARCH_ROOT`. Для production deployment нужны persistent volume,
readiness check, single-writer discipline и documented rebuild. Index нельзя
класть в blob store как authoritative state.

## API contract 0.4.0

Точные request/response schema фиксируются ADR и compatibility fixtures.

### Annotations

```text
GET    /api/v1/materials/{material_id}/annotations
POST   /api/v1/materials/{material_id}/annotations
GET    /api/v1/materials/{material_id}/annotations/{annotation_id}
PUT    /api/v1/materials/{material_id}/annotations/{annotation_id}
DELETE /api/v1/materials/{material_id}/annotations/{annotation_id}
GET    /api/v1/materials/{material_id}/annotations/export
```

Существующие routes сохраняются. List получает cursor, filters и
`include=links,backlinks,audio`. Mutations сохраняют `Idempotency-Key` и
`expected_revision`.

### Audio blobs

```text
POST /api/v1/blobs/uploads
PUT  /api/v1/blobs/uploads/{upload_id}
POST /api/v1/blobs/uploads/{upload_id}/complete
GET  /api/v1/blobs/{hash}
```

Это generic contract `CORE-014`, поставленный `0.3.0`. `0.4.0` переиспользует
его без нового uploader, recorder или blob lifecycle. Complete возвращает
immutable `AudioAttachment` ref, после чего отдельная annotation command
связывает его с voice note.

Download:

- проверяет `user_id` ownership через referencing annotation/material;
- поддерживает range requests, если это нужно browser playback;
- возвращает исходный safe media type и `nosniff`;
- не раскрывает storage path/key.

### Links

```text
GET  /api/v1/links/suggest?q=&material_id=&cursor=
POST /api/v1/links/resolve
GET  /api/v1/links/backlinks/{object_type}/{object_id}
```

Resolution учитывает current material как ranking boost, но ambiguous target
не выбирается молча.

### Desk

```text
GET /api/v1/desk/materials
GET /api/v1/desk/materials/{material_id}
GET /api/v1/desk/items
GET /api/v1/desk/items/{object_type}/{object_id}
```

Обязательные query fields:

- cursor и bounded page size;
- material/type/structural group/tag/status/date;
- learning state/due range и artifact kind/acceptance state;
- has note/has transcript/unresolved/conflicted;
- source order/updated/created/material title/relevance;
- projection version в диагностическом metadata.

### Search

```text
GET  /api/v1/search?q=&scope=&type=&material_id=&cursor=
POST /api/v1/search/retrieve
GET  /api/v1/search/status
```

Response возвращает stable open target, snippet, source metadata, anchor,
matched fields и score breakdown в debug mode.

### RAG

```text
RecordSearchScope {
  query?
  material_ids[]
  record_types[]
  tags[]
  statuses[]
  updated_range?
  retrieval_version
}
```

Новые answer/session routes не добавляются. Используются conversation/message/
generation routes из `0.2.0`. Message получает явный `RecordSearchScope`
context attachment. Server разрешает его в permission-aware
`RetrievedChunk[]`, сохраняет chunk ids/hashes в context pack и использует
существующий streaming transport. Если transport `0.2.0` меняется, меняется
adapter, а не `RecordSearchScope`/`RetrievedChunk`/citation contract.

## Web UX и маршрутизация

### Route state

Текущий hash router нужно вынести из `account.rs` в отдельный typed route
contract. Для текущего static SPA допустимы hash URLs, если reload и browser
history полностью восстанавливают state:

```text
#/desk
#/desk/records
#/desk/learning
#/desk/artifacts
#/desk/material/{material_id}
#/desk/material/{material_id}/records
#/desk/material/{material_id}/learning
#/desk/item/{object_type}/{object_id}
#/search?q=...
#/reader/{material_id}?anchor=...
```

Route state включает filters, sort, selected material/item и query. Display
titles не входят в primary URL.

### Reader

Selection toolbar:

- yellow;
- bold;
- note;
- voice note;
- открыть/изменить существующую запись;
- link action внутри note composer.

Margin-note action:

- desktop: semantic margin affordance у текущего блока;
- compact/touch: действие «Запись на полях» в block/page actions;
- без selection создается whole-block/section/page target;
- marker имеет label, keyboard focus и не является единственным способом
  открыть запись.

Notes panel:

- tabs All/Notes/Highlights/Voice;
- фильтр current section;
- source-order list;
- inline edit с conflict recovery и сохранением local draft;
- wikilink autocomplete;
- playback и transcript state;
- переход «Все записи в Desk».

### Desk

Первый экран `/desk`:

- material groups с counts и last activity;
- cross-material «Все записи»;
- attention block для unresolved/conflicted/missing audio;
- отдельные capability-backed views learning state и сохранённых typed
  artifacts без копирования их primary data.

Material Desk:

- overview;
- records grouped by heading path/chapter/PDF page;
- learning items, attempts, due state и mastery summary;
- сохранённые typed AI artifacts с provenance и source refs;
- filters и source-order/updated sorting;
- inline edit;
- переход в reader на anchor;
- переход в Challenges или artifact detail;
- previous/next record navigation.

Mobile:

- list/detail navigation вместо постоянных трех колонок;
- filters в sheet;
- item actions доступны с keyboard/touch semantics;
- audio controls имеют текстовые labels.

### Search

Global search:

- один input с type/material filters;
- grouped results «Материалы», «Записи», «Обучение» и «ИИ-артефакты»;
- result snippet, type, material, structural path и match reason;
- open in Desk либо reader at anchor;
- loading, index rebuilding, partial index и no-text states.

Library search/filter использует тот же query contract и material open targets,
но не индексирует отдельную копию library metadata.

Reader search:

- `material_id` scope;
- подсветка найденных фрагментов не конфликтует с user highlights;
- next/previous match;
- fallback linear search только для bounded small document, пока index строится.

### RAG по записям

В search/Desk доступно действие «Спросить по записям»:

- до отправки видны scope и filters;
- действие открывает или разворачивает глобальный чат `0.2.0` и добавляет
  явное record-scope attachment;
- в context попадают только records и разрешенный source context;
- ответ стримится в обычном chat lifecycle, а не внутри списка search results;
- каждая citation открывает Desk item или reader anchor;
- при слабом retrieval UI сообщает о недостаточном контексте;
- ответ не превращается в note автоматически;
- отсутствие BYOK показывает настройку provider, а не скрытый fallback.

## Search design

### Индексируемые sources в 0.4.0

- material title/authors/source/tags/language;
- normalized headings, paragraphs и PDF text blocks;
- highlight quote плюс source context;
- note/margin note title, Markdown text, tags и resolved link labels;
- linked voice `TranscriptArtifact`, если он принят и доступен;
- accepted/saved typed AI artifacts с source refs; raw chat, intermediate
  generations и rejected drafts исключены;
- active/accepted learning items и source-backed explanations по явной
  learning search policy;
- structural path и citation metadata.

Речь только о transcript artifact, явно связанном с `VoiceNote`. Learning
answer transcripts и raw attempt answers из `0.3.0` по умолчанию не
индексируются: для них требуется отдельная явная search policy. Audio без
transcript не индексируется по содержимому, но находится по material, type,
tags и metadata.

### Chunking

- material: heading-aware paragraphs/windows;
- PDF: page/block-aware windows;
- highlight: одна запись, quote и bounded source context;
- note/margin note: heading sections/paragraphs;
- transcript: time-bounded paragraphs с voice-note citation;
- stable chunk id строится из source id, source revision, field и chunk ordinal;
- chunker version участвует в invalidation;
- длинный text получает overlap, results проходят dedup/grouping.

### Ranking

```text
query parse
  -> ownership/scope filters
  -> BM25 top N
  -> fastText query/chunk similarity
  -> weighted fusion
  -> exact/title/tag/current-material boosts
  -> dedup and source diversity
  -> snippets and open targets
```

Отдельные ranking profiles:

- global user search;
- reader current-material search;
- Desk records search;
- AI retrieval.

AI retrieval по умолчанию предпочитает разнообразие sources и пригодность
цитаты, а не несколько соседних chunks одного текста.

### fastText spike

До выбора dependency проверить:

- Russian/English mixed queries и subword behavior;
- pure Rust против bounded native binding;
- `unsafe_code = forbid` на стороне Lumi;
- Linux server build и будущую применимость на desktop/mobile;
- model license, checksum, размер и обновление;
- cold start, query latency, memory и 500k chunks;
- способ хранения/вычисления vectors;
- поведение при отсутствии model file.

Результат spike: ADR с выбранным runtime/model/version, benchmark corpus и
fallback behavior. `0.4.0` не считается готовым только с BM25, если fastText
rerank отключен в обычной конфигурации.

## План поставки

Поставка делится на три параллельных трека после общего подготовительного
gate. Треки владеют разными модулями и могут использовать fixture-backed

скрытое дублирование domain/provider/blob logic.

- [ ] ADR: internal `LinkTarget`, unresolved/ambiguous links и backlinks.
- [ ] ADR: search chunks/retrieval API/Tantivy storage/index rebuild.

- [ ] bold overlay/pagination browser spike и ADR.

      `SearchChunk`, `SearchResult`, `RetrievedChunk`, `RecordSearchScope`.
- [ ] сверить реализованный contract `0.2.0`: не дублировать `AiProvider`,
      SecretStore, conversation/generation routes и context pack.

- все schema/search/blob решения описывают compatibility impact и required

MediaRecorder/provider используются через deterministic test adapters.

### Performance

Нужно превратить design targets из `quality.md` в executable budgets:

- 10k materials / 500k chunks: first global search page;
- 100k annotations: Desk first page, material group and counters;
- 100k learning/artifact projections: material Desk и filtered search page;
- annotation create/update perceived latency с optimistic UI;
- incremental index update after note save;
- cold index/projector rebuild throughput;
- 10-minute allowed voice upload/playback start;
- fastText model cold start, memory и query rerank latency.

Точные p95 thresholds утверждаются по результатам spikes и фиксируются рядом с
dataset, чтобы их нельзя было ослабить без причины.

## Security и privacy

- Все Desk/search/retrieval queries начинают с account/scope authorization.
- Private annotation не попадает в Community/shared index.
- Audio upload проверяется по bytes/signature, а не только filename/MIME.
- Blob hash не является bearer credential.
- Media download использует authorization, `nosniff`, bounded ranges и safe
  content disposition.
- Markdown renderer не исполняет raw HTML/JS.
- Search snippets экранируются и не являются trusted markup.
- RAG source text рассматривается как untrusted data, не как instruction.
- Пользователь видит scope/context до AI call.
- Note/audio/transcript/provider secret не попадают в обычные logs.
- Provider key хранится только в server secret storage и не синхронизируется
  plaintext.
- Rate/size/time limits применяются server-side.
- Export явно сообщает, включает ли он audio bytes или только manifest.

## Observability и эксплуатация

Метрики:

- annotation commands по type/result/conflict;
- audio upload bytes/duration/failure и orphan cleanup;
- Desk projection lag/rebuild duration/version;
- index queue depth/lag/failures/rebuild duration;
- query latency, candidate count и rerank latency;
- zero-result rate без записи query text в обычную telemetry;
- retrieval chunks/source diversity;
- RAG provider latency/cancel/error/token usage без body/context;
- unresolved anchors/links.

Readiness:

- database/blob store остаются обязательными как сейчас;
- search status различает `ready`, `partial`, `rebuilding`, `failed`;
- отсутствие fastText model делает search capability degraded/failed согласно
  ADR, а не молча меняет ranking;
- AI provider failure не делает Desk/обычный search unavailable.

Runbook должен описывать:

- rebuild Desk projection;
- rebuild Tantivy/fastText derived state;
- replace/version fastText model;
- recover stuck index jobs;
- inspect orphan audio without reading user content;
- disable RAG provider while keeping retrieval/search available.

## Rollout и rollback

Порядок rollout:

1. применить additive schema;
2. развернуть dual-compatible server;
3. выполнить annotation backfill;
4. построить Desk projection;
5. построить search index и проверить version/status;
6. включить reader v2;
7. включить Desk;
8. включить search;
9. включить voice upload;
10. включить record-scope attachment в глобальном чате отдельным
    capability/feature flag.

Rollback:

- до destructive cleanup старый payload сохраняется читаемым;
- Desk/search projections можно удалить и перестроить;
- отключение search/RAG не блокирует Reader/Desk primary CRUD;
- новые annotation types старый server не должен молча перезаписывать;
- blobs не удаляются при rollback до завершения retention window;
- schema contraction выполняется только отдельным будущим релизом после
  подтвержденной совместимости.

## Риски и способы снижения

| Риск | Последствие | Снижение |
| --- | --- | --- |
| Bold меняет layout | неверные страницы и overlays | обязательный spike, paint-only либо versioned repagination |
| Annotation v2 ломает старые записи | потеря пользовательских данных | additive migration, dual decoder, golden fixtures, rehearsal |
| Audio codec не поддерживается browser | voice flow недоступен | MIME negotiation, capability response, file fallback |
| Orphan/duplicated blobs | рост storage или раннее удаление | complete + reference transaction, refcount, grace period |
| Desk projection расходится с primary state | неверные counts/items | outbox, cursor/version, deterministic rebuild |
| Search index отстает | запись не находится | lag state, retry/rebuild, primary Desk остается доступным |
| fastText dependency усложняет build | release/platform failure | timeboxed spike, model checksum/license, explicit runtime ADR |
| Record RAG раскрывает лишние notes | privacy incident | pre-retrieval scope filters, context disclosure, access tests |
| Source prompt injection | неверный AI behavior | data delimiters, fixed system policy, citations, no tools |
| Wikilink names ambiguous | ссылка ведет не туда | stable ids, picker, unresolved state, no silent first match |
| Scope разрастается до KB/chat | релиз не завершается | явные non-goals и capability boundaries |

## Completion criteria 0.4.0

Релиз считается завершенным, когда одновременно выполнено следующее:

- Gate 0, треки A/B/C, Gate I и общий Release gate закрыты либо отдельный
  пакет явно вынесен из scope через обновленный канонический документ;
- current annotations мигрируют без потери ids, anchors, bodies, revisions и
  tombstones;

  поддерживаемых reader surfaces;

  filters, inline edit и source navigation;

  (`DESK-005`) поверх primary contracts `0.2.0`/`0.3.0`;
- MCP перечисляет Desk items и выполняет search через те же permission-aware
  query services, что Web;
- BM25 + fastText search индексирует sources релиза, инкрементально
  обновляется, перестраивается, соблюдает ownership и обслуживает
  Library/Global/Reader/Desk surfaces;
- RAG по записям расширяет глобальный чат `0.2.0`, использует общий retrieval
  contract, bounded visible context и проверяемые citations;
- export/backup/restore покрывают новые primary данные;
- отсутствуют известные пути утечки foreign/private record или audio;
- executable performance budgets проходят;
- `make c` проходит;
- `make web-e2e` проходит для desktop и добавленных compact/touch flows;
- runbooks позволяют оператору диагностировать projection, index, model,
  audio и provider failures;
- durable decisions из этого плана перенесены в ADR/`docs/systems/`.
