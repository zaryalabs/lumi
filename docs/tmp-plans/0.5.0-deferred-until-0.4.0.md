# 0.5.0: отложено до готовности 0.4.0

Status: `complete`

Последнее обновление: 2026-07-27

## Результат

Все зависимости 0.4.0 закрыты, а перечисленный ниже функционал реализован.
Принято решение
[`ADR 0040`](../adr/0040-shared-reading-social-index-images-and-fingerprint-lifecycle.md).
Capabilities `shared-reading`, `social-search-index` и `community-images`
публикуются persistent server. Этот файл сохранён как release evidence; он
больше не является блокирующим dependency record.

## Назначение

Этапы `0.5.0/E1–E4` выполняются параллельно с `0.4.0`. Этот документ фиксирует
части social-плана, которые нельзя честно реализовать или включить до release
evidence соответствующих contracts 0.4.0. Они не заменяются временными social
моделями и остаются выключенными capability flags.

## Отложенные пункты

### Annotation v2, private records и shared anchor

Зависимости: `0.4.0/E1`, `0.4.0/E2`, `RD-006`, `RD-009`, `CORE-015`.

- ADR shared anchor contract и fixtures cross-copy anchor mapping;
- `SharedAnchorDraft` из Annotation v2 target;
- section/anchor/page threads и комментарии с provenance private record;
- explicit publish/unpublish highlight как отдельной shared entity;
- Reader social panel, selection actions и reflowable/PDF overlay;
- cursor mapping относительно текущей revision и honest unresolved placement;
- проверки private note isolation и unresolved mapping.

Причина: social не должен вводить второй target/record contract или расширять
текущий private `Annotation` полем visibility.

До готовности этих зависимостей capability `shared-reading` не публикуется.
Реализованный независимо `material-discussions` не принимает anchor, quote,
private annotation/material/revision и не считается Reader social layer.

### Serious search и permission-aware social index

Зависимости: `0.4.0/E3`–`E5`, `SEARCH-001`, `SEARCH-003`.

- capability `social-search-index`;
- permission-bearing index events;
- invalidation по membership/claim/moderation;
- benchmarks и cross-Space search isolation.
- MCP search tools по shared comments/chat;
- E4 invalidation events для edit/delete, membership removal, claim и
  moderation transitions;

Причина: до готовности общего search/index runtime social не создаёт отдельный
индекс и не публикует capability.

Независимый E4 публикует chat/activity и MCP CRUD parity, но не
`social-search-index`: chat/comment bodies не отправляются во временную очередь
и не индексируются вторым social-only механизмом.

### Generic image blobs для avatar/cover

Зависимость: подтверждённый generic upload/download/refcount contract
`CORE-009` в baseline, совместимый с 0.4.0 records/audio consumers.

- avatar/cover upload и image validation;
- Space-authorized download;
- replacement/refcount/retention.

Причина: текущий blob слой хранит import/audio artifacts, но не предоставляет
принятый generic image mutation contract. E1 сохраняет name/description и
скрывает image customization.

### Автоматический fingerprint lifecycle после E2

Зависимости: финальные revision/record/open-target hooks `0.4.0`.

В `0.5.0/E2` уже реализованы:

- принятый
  [`ADR 0037`](../adr/0037-material-fingerprints-and-community-claims.md);
- versioned extractors текущих normalized packages EPUB, PDF, Web, Telegram,
  Markdown и LUM;
- server-internal protected fingerprints;
- shared identities, claims, conservative match/manual review и recheck;
- capability `material-sharing` для persistent server.

До готовности 0.4.0 остаются отложены только lifecycle-интеграции, которые
нельзя привязать к ещё меняющемуся revision/open-target contract:

- enqueue `Job(kind = material_fingerprint)` после каждого successful import,
  revision switch и будущего records migration;
- массовый durable backfill всех существующих ready revisions;
- автоматическая re-evaluation claims при появлении новой active revision;
- ISBN/DOI/canonical URL evidence из будущего расширенного metadata/record
  contract;
- invalidation/rebuild, связанная с общим search/open-target lifecycle.

До этого explicit share/claim/recheck вычисляет fingerprint текущей immutable
active revision в bounded request path. Capability не обещает автоматический
background backfill или cross-revision re-evaluation.

## Уже реализованная независимая часть E1–E3

- отдельные CommunitySpace/SyncSpace identities;
- scoped membership/role permission policy;
- create/list/detail/update/delete Space;
- encrypted, hashed, revocable/rotatable 256-bit link access;
- safe preview и explicit join;
- membership list, role update, remove и leave;
- Community Web shell и capability-aware unavailable states;
- atomic sync projection, idempotency и system activity.
- explicit material share/claim/recheck для текущей immutable active revision;
- server-internal protected fingerprints, shared identity dedup и
  manual-review states без публикации source blob.
- material-level threads и одноуровневые replies без claim/quote/source body;
- author edit/delete с expected revision, tombstones и idempotency;
- owner/admin hide/restore/delete с append-only moderation audit;
- bounded cursor delivery и Web discussion surface в карточке shared material;
- capability `material-discussions` и
  [`ADR 0038`](../adr/0038-material-discussions-and-moderation.md).

## Уже реализованная независимая часть E4

- отдельные cursor-paginated Space chat и append-only activity projection;
- author edit/delete, moderator hide/restore/delete и tombstones;
- bounded polling chat/activity/open discussion с visibility pause, backoff,
  dedupe и сохранением уже загруженного cursor page;
- social MCP registry `mcp-tools.v4` поверх тех же application services;
- publish-rate limits, redacted diagnostics и vendor-neutral alert;
- performance dataset, multi-account Web E2E и backup/restore evidence с
  revoked links.

Отложенные пункты закрыты migration
`20260726340000_deferred_social_reading.sql`, domain/application/Web changes,
privacy/cross-Space/image tests и общими quality gates.
